# f16 and f128

## f16: soft-lowered

An `f16` value is its 16 bits, zero-extended in a wasm `i32`, the same canonical form
as `i16`. `map_type` maps `f16` to `I32`; entry params, block params and call results
re-mask to 16 bits. Bitcast to and from `i16`, `select`, calls, returns, `f16const` and
16-bit `load`/`store` are plain integer moves. `fneg`, `fabs` and `fcopysign` are bit ops.

All arithmetic goes through `src/ops/f16.rs`:

- `f16 -> f32` is exact: shift the magnitude into place, multiply by `2^112` to
  normalize subnormals, and patch the exponent for inf/NaN. NaN payloads are kept.
- `f32 -> f16` rounds to nearest even with integer ops plus one float add for the
  subnormal range. Out-of-range values become inf; NaN stays NaN and keeps its top
  payload bits with the quiet bit set.
- `f64 -> f16` first narrows to `f32` with round-to-odd (nudge an inexact, even result
  one ulp toward the source), then rounds to `f16`. Plain `f64 -> f32 -> f16` double
  rounds.
- `fadd`, `fsub`, `fmul`, `fdiv`, `sqrt`, `fmin`, `fmax`, `ceil`, `floor`, `trunc`,
  `nearest` and `fcmp` run in `f32`. For the first five, `f32` has at least `2p+2`
  bits of the 11-bit `f16` significand, so rounding twice is exact; the rest do not round.
- `fcvt_from_{s,u}int` from `i8`/`i16`/`i32` converts to `f64` (exact) and rounds once.
- `fcvt_to_*int` and `fpromote` promote to `f32` or `f64` first.

Unsupported, each with an error naming the opcode: `fma` on `f16`, `fcvt_from_*int`
from `i64` and `i128` (the intermediate float would round first), and `f16` vectors.

NaN results from arithmetic are whatever wasm `f32` produces, narrowed; payloads are not
specified.

`tests/f16.rs` checks every `f16` bit pattern for promotion and unary ops, all
midpoints and near-midpoints for demotion, and a sample cross product for binary ops.
The Cranelift interpreter cannot execute `f16` arithmetic, so the reference is exact
`f64` math plus a search-based nearest-even rounder, not the interpreter.

## f128: documented boundary

`f128` signatures and values fail with `E2001`. Wasm has no quad float and the
only route is a full soft-float library (add, mul, div, sqrt, fma, compare, every
conversion) shipped as runtime helpers like `__clif2wasm_fma_*`. Nothing in the current
consumers needs it, so it is not built. Revisit if a frontend emits `f128`
operations; the helpers would take and return `i128` pairs, which the ABI already
carries.
